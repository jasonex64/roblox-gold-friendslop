# EXP-004 — T-040 technical integration
Date: 2026-10-26. Owner: yukicide. Not a human playtest.

Hypothesis: Session/Shift produce a frozen reward snapshot with all admitted
participants, including one who leaves late; replay cannot discard an undurable
manifest; explicit recovery applies once and replay preserves saved progress.

Expected: two synthetic participants, one active for 490 seconds and one AFK,
crew haul 12000: eligible participant gets 32 provisional tokens, other gets zero.
Injected failed writes block replay, then recovered writes allow replay with
cash/haul/inventory reset and permanent tokens retained.

Method written before execution: run tests/studio/GateDRewards.luau through the
existing Studio connector in Edit mode. Instantiate isolated Session/Shift with
synthetic roster IDs, injected clock and JSON in-memory store. Do not start Play,
enable API access, publish the place, or access a real datastore. Source reaches
Studio through Rojo only; cloned modules are executed unchanged for verification.
Unit tests separately cover AFK/discovery boundaries, duplicate settlement, failed
loads, lost acknowledgements and restart. No human enjoyment/retention claim.

Fallback method (recorded before execution): if Studio cannot reconnect to Rojo, execute the same fixture under Lune with actual Session/Shift source and injected service mocks. This is deterministic integration evidence, not engine or UI evidence.

Result: Studio connector execution stopped before assertions with
`RewardFlow is not a valid member of Script "ServerScriptService.Server"`.
A restarted Rojo server on port 34872 did not reconnect the existing plugin;
connector inspection still returned `false` for RewardFlow's existence. No
Source edits, desktop control, real datastore writes or Play session occurred.
The fallback passed under Lune: `ShiftRewards.spec.luau :: SHIFT actual Session
and Shift retain offline rewards, block failed replay and reset safely`.
The full gate reports `unit: 162 passed, 0 failed` and `ALL CHECKS PASSED`.

Conclusion: deterministic server integration is verified, including the 490s /
32-token departed recipient, failed-store replay barrier, recovery and reset.
Engine execution, live datastore behavior and visual UI remain unverified.
This does not close Gate D or retroactively pass skipped Gate C playtests.
