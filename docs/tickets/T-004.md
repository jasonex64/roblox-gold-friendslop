#### Bell cutoff: explicit choice required

T-003 Q18 preserves DESIGN's completion-at-or-before-end proposal. The implementation instead advances the run and settles it before processing production (`src/server/init.server.luau`, `src/shared/Pure/Run.luau`, `src/shared/Pure/Settlement.luau`). This can discard a pending sift whose final timeout was due before the bell if the next server update arrives after the bell. An accepted final press already completes synchronously and is sold; it does not wait for that update.

- **A — Keep the current cutoff:** sell only finds already completed by the server before the bell; discard every still-pending sift, even when its timeout was due before the bell.
- **B — Count sifts due by the bell (recommended):** complete and sell a valid sift whose authoritative completion deadline is at or before the bell, even if the server update processes it late. Reject new player actions at/after the bell and continue to discard raw dirt and unfinished work. This matches Q18's proposed boundary and prevents update delay from losing an already-due payout. It requires a code correction and focused regression tests before acceptance.

Both choices retain server authority; client-provided press timestamps must not grant retroactive rewards. Existing green tests encode A and do not establish B. No new playtest or experiment was run to select a rule. Implementation note for an approved B correction: run/dig timing currently uses `os.clock()`, while sifting uses `workspace:GetServerTimeNow()`; these deadlines must not be compared directly without one consistent authoritative clock basis. Preserve contact/cancellation checks when resolving due work.
