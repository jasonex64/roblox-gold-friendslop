## Goal
A first-time player can find and do dig, sift, sell, upgrade, and finish with clear controls and a HUD driven by server state.
Source: DESIGN §1, 5, 14-16 (Gate A, R01/R13); D-004, D-008.

## Why
Who uses it: first-time players.
What breaks without it: a correct server loop is still unusable.

## Acceptance criteria
- [x] Contextual actions work on keyboard/mouse and touch, including the skill check; non-sifting actions need no rapid clicking; invalid actions say why — test: UX-1
- [x] HUD shows timer, phase, Crew Haul, personal cash, bucket fill, and next action from server state — test: UX-2
- [x] Guidance explains dig/sift/sell/upgrade, temporary purchases, and end-of-run discard without relying on hover or sound — test: UX-3

## Out of scope
- Class, pet, lobby, or shop screens
- Telemetry platform

## Numbers used
- Values come from `src/shared/Config.luau` (D-011): approved `D-###`, else `PROVISIONAL DESIGN §N`. Gate A inventory: T-003 ND list.

## Test plan
UX-1: perform every action per input type incl. cancel and full paths. UX-2: compare HUD to server values via `execute_luau`. UX-3: a human follows prompts unaided; record confusion.
