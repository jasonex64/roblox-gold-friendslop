## Goal
The server records each player's digging, sifting, sluice loading, selling and sluice funding with T-026's Contributions module, and the end-of-shift results screen lists one line per player.
Source: DESIGN §4 (result screen shows each player's useful contributions), §6 (record them separately), §15 Gate C.

## Why
Who uses it: every crew at the bell; T-022 playtesters judging whether teammates helped.
What breaks without it: the results screen shows only Crew Haul, so nobody can see who dug, sifted or funded.

## Acceptance criteria
- [x] Credit is recorded only at committed actions (finished dig, completed sift, sluice load, sale with value, sluice contribution) with shift-unique event IDs; a duplicate event errors loudly — test: unit RESULT-1 plus Studio check
- [x] The results screen lists every contributing player, including players who left, with dug, sifted, sluice-loaded, sold and funded totals; the sold totals add up to Crew Haul — test: RESULT-2 plus Studio check
- [x] Replay starts a fresh, empty credit record — test: Studio check
- [x] All repository gates pass

## Out of scope
- Personal bests, tokens, pets, discoveries, next unlock, results timer and lobby

## Numbers used
- None. Layout sizes are UI geometry, not gameplay numbers.

## Test plan
`lune run tests/run unit` for the Hud formatter (RESULT-1..2); Studio MCP playtest: dig, sift, sell, then end the shift and read the results attributes and screen.
